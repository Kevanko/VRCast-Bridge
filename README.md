# VRCast Bridge

Экран, окно, видео или плейлист — одной ссылкой в видеоплеер VRChat.

## Что делает

Берёт то, что происходит у вас на компьютере, и отдаёт одной ссылкой для видеоплеера в мире VRChat. Ссылка не меняется, пока программа открыта: можно переключать видео, ставить паузу, переходить с плейлиста на захват экрана — плеер в мире продолжает играть, resync жать не нужно.

Задержка от действия до картинки в VRChat — около полусекунды. Обычные способы через HLS дают три и больше.

## Возможности

**Медиа-очередь.** YouTube и плейлисты, VK, Rutube, прямые ссылки на `.mp4` и `.m3u8`, файлы с компьютера. Ролики перетаскиваются мышью, у каждого на превью видна длительность. Пауза, перемотка, скорость, повтор, сохранённые списки. Нескачанный ролик включается сразу из сети, а на диск докачивается фоном — следующие переключения идут мгновенно. Большой плейлист программа сначала предложит подтвердить.

**Аниме.** AnimeLib и сайты с плеером Kodik: вставьте ссылку — откроется окно, где выбираются серия, одна или весь сезон, озвучка и качество. Длительность серий видна сразу, скачиваются только ближайшие.

**Захват.** Монитор, отдельное окно, произвольная область или все мониторы сразу. Окно захватывается через Windows Graphics Capture, поэтому чужие окна поверх него в кадр не попадают.

**Одна ссылка на всё.** Эфир переключается с плейлиста на захват экрана и обратно одной кнопкой — плеер в мире не переподключается.

**Звук.** Системный, конкретного приложения, отдельного выхода или микрофон. Приложение можно приглушить в своих наушниках, оставив полную громкость в эфире — помогает, когда слышишь звук дважды: свой напрямую и его же с задержкой из VRChat.

**Для друзей.** Бесплатная быстрая ссылка без регистрации — Cloudflare, Serveo или localhost.run. Программа меряет скорость каждого сервиса и в «Авто» берёт самый быстрый. Если есть VPS с белым IP, она развернёт на нём медиасервер сама — по SSH, за минуту.

**Мимо VPN.** Если включён VPN, поток до своего сервера и быстрые ссылки можно пустить напрямую через выбранную сетевую карту — остальной компьютер остаётся за VPN.

**Не мешает игре.** На простое программа почти не нагружает процессор. Процессы эфира идут с повышенным приоритетом, поэтому игра и браузер их не вытесняют, а фоновые загрузки — с пониженным. Если машина не тянет выбранное качество, программа сама снижает нагрузку и следит, чтобы задержка не росла.

**Настройки в одном окне.** Шестерёнка сверху: три темы оформления («Ночной мир», «Эфирная», «Проектор»), кодировщик, способ быстрой ссылки, папка и объём скачанных видео.

**Живой фон.** Мягкий перелив цветов темы дышит в такт музыке эфира, а вокруг плеера разливается свет от самой картинки. Отключается в «Оформлении».

**Работает из трея.** Крестик прячет окно, эфир продолжается; значок в трее открывает программу или останавливает эфир. Можно переключить, чтобы крестик закрывал программу.

**Автообновление.** Программа сама находит новую версию и ставит её по кнопке «Обновить».

## Установка

Скачайте [VRCast Bridge.exe](https://github.com/Kevanko/VRCast-Bridge/releases/latest) и запустите — программа сама предложит папку и ярлык.

Всё недостающее — Node.js, FFmpeg, загрузчик видео, медиасервер и WebView2 — она докачает при первом запуске. Ставить руками ничего не нужно.

## Linux

Запуск из исходников (нужны Node.js 20+ и `ffmpeg`; `yt-dlp`, MediaMTX и cloudflared программа докачает сама или возьмёт из `PATH`):

```bash
git clone https://github.com/Kevanko/VRCast-Bridge.git && cd VRCast-Bridge
npm ci && ./bin/vrcast install      # зависимости и оболочка (Electron)
ln -s "$PWD/bin/vrcast" ~/.local/bin/vrcast
vrcast                              # окно приложения; vrcast stop|status|log
```

Оболочка (`desktop/`, Electron) повторяет Windows-версию: окно со страницей сервера, значок в трее (в GNOME нужно расширение AppIndicator), крестик прячет в трей, вопросы при выходе про идущий эфир и несохранённый список, перетаскивание файлов, выбор области экрана и подсветка источника, запоминание размера окна. Без неё `vrcast` откроет окно Chrome. Данные лежат в `$XDG_DATA_HOME/VRCastBridge` (по умолчанию `~/.local/share/VRCastBridge`), адрес — `http://127.0.0.1:4717`.

| Что | Как работает в Linux |
|---|---|
| Экран, монитор, область, окно | X11 через `x11grab`; список мониторов — `xrandr`, окон — `xprop` и `xwininfo`. В Wayland захват идёт через XWayland и видит только X11-окна |
| Звук | PulseAudio / PipeWire (`pw-dump` или `pactl`): системный звук, выбранный выход или микрофон. Звук одного приложения не вырезается — берётся весь системный |
| Автообновление, захват окна через Windows Graphics Capture, регулировка звука приложений | Только Windows |

Если MediaMTX не стартует с ошибкой `inotify: too many open files`, поднимите лимит: `sudo sysctl fs.inotify.max_user_instances=512`.

### Приложение для телефона (Android)

Приложение из `mobile/` (Flutter) одно и работает с ПК и без него: отдельного режима нет. Телефон хранит у себя файлы, серверы и копию настроек ПК; когда подключён к ПК, они объединяются в группу.

- **Устройства в сети.** В настройках ПК включите «Пульт для телефона»: ПК объявится в сети (`_vrcast._tcp`). Приложение показывает найденные ПК под их именами, замком отмечает защищённые PIN-кодом, а любое устройство можно назвать по-своему (имя хранится на телефоне). Имя ПК и необязательный PIN задаются в его настройках («Имя этого ПК в сети», «PIN для подключения»), там же список привязанных устройств с переименованием и отвязкой. PIN защищает управление; сам поток в сети открыт, как и ссылка RTSP.
- **Эфир в реальном времени** (SSE `/api/events`): что играет, статус, превью, очередь, ссылки; пауза, перемотка, скорость, повтор, громкость, переход по очереди.
- **Группа устройств.** ПК, к которому подключились, — админ; все подключённые устройства равны. Файлы и серверы каждого видны всем в общем списке с пометкой владельца, пока устройство подключено; отключилось (через 15 с без связи), и они пропадают у остальных. Файлы остаются на телефоне, ПК играет их по сети (`/api/media/<id>?k=<ключ>` на телефоне, ключ у каждого запуска свой). Эфир один, на одной ссылке, и им управляет тот, кто начал последним; перехватить его можно с любого устройства кнопкой «Перехватить». Остановить эфир, сменить очередь или ссылку может любое устройство. Убрать устройство из группы может только админ (ПК); если кто-то убрал чужой файл из очереди, владелец узнаёт об этом и убирает его у себя. Пока телефон спит или приложение закрыто, его файлы недоступны ПК.
- **Своя очередь без ПК.** Без ПК очередь телефона работает сама: добавьте ссылку на YouTube (видео или плейлист, как на ПК: большой плейлист переспрашивает), прямую ссылку на mp4 или файлы с телефона. У каждого ролика название, длительность и обложка, их можно перетаскивать и смахивать. Ссылку телефон разбирает сам; поток берётся прямо перед запуском. Поток YouTube — готовый mp4 (H.264 + AAC), его качество определяет YouTube (обычно до 360p, у части роликов выше нет); для HD нужен ПК. Остальные ссылки (VK, Rutube, Twitch, аниме, прямые трансляции) телефон не разбирает: они ждут подключения к ПК и уходят в его очередь, туда же уходят ссылки из своей очереди. Очередь ПК без связи лежит отдельно (последняя копия, только для справки).
- **Эфир файлов с телефона без ПК.** Когда ПК не подключён, вкладка «Сейчас» становится плеером своей очереди (пауза, перемотка, следующий и предыдущий, повтор). Нажмите на свой файл в «Очереди» или «Начать эфир файлов». Видео не перекодируется: приложение разбирает mp4/mov/m4a и отправляет кадры H.264 и звук AAC как есть, поэтому телефон не греется, а аппаратный кодировщик не нужен. Другие форматы (HEVC, MKV, mp3 и т. п.) пропускаются с пояснением. Вещать можно двумя способами, переключатель на той же вкладке:
  - **Свой сервер.** RTSP на ваш VPS, ссылка `rtspt://адрес:порт/phone` (та же, что у экрана телефона).
  - **Ссылка Cloudflare.** Бесплатная ссылка `https://….trycloudflare.com/stream/live.m3u8` прямо с телефона: приложение само раздаёт HLS, а `cloudflared` (внутри приложения) выводит его в интернет. Ссылка живёт, пока идёт эфир и приложение открыто. Мешают VPN, которые подменяют DNS или рвут порт 7844 (то же, что и на ПК).

  Пока идёт эфир, работает служба переднего плана (с уведомлением): экран можно гасить, и эфир не оборвётся. Эфир с телефона разряжает батарею и держит Wi-Fi включённым.
- **Экран или приложение с телефона в эфир.** Кнопка «Транслировать экран телефона» одна, путь выбирается сама: если ПК на связи, поток идёт через него (по WebRTC в MediaMTX на ПК, ПК кодирует эфир), иначе прямо на ваш сервер (VPS из `server/install.sh`, H.264). Android спрашивает: весь экран или одно приложение. Звук с телефона пока не передаётся.
- **Телефон подстраивается под ПК.** Сводка эфира всегда берётся с ПК, а запись экрана идёт в том же профиле: качество, частота кадров и битрейт следуют за настройками ПК.
- **Без связи.** Очередь, настройки и ссылки ПК сохраняются на телефоне и показываются без связи. Ссылки, добавленные без ПК, уходят в очередь ПК при подключении. Серверы личные: подключённое устройство делится ими с группой только на время подключения (для этого нужна привязка по коду), на самом ПК они не сохраняются.
- **Эфир на ПК с телефона.** Куда идёт эфир (локально, публичная ссылка, свой сервер), сервис быстрой ссылки, выбор сервера, прямой адрес, качество, кадры, кодировщик. Это требует привязки: код из «Настройки → Программа → Код привязки телефона» (или PIN ПК) вводится один раз. Без привязки настройки видны, но не меняются.
- **Что остаётся только на ПК:** порт, папка кеша, доступ из сети, имя ПК и PIN, добавление серверов по SSH, обновления, завершение программы. Подключение групп «телефон ↔ телефон» и «ПК ↔ ПК» пока не поддерживается: админом может быть только ПК.

Для работы телефона без ПК сервер на VPS должен быть установлен или обновлён скриптом из этого репозитория («Настроить с нуля» в программе): он включает приём WebRTC и путь `phone`; ссылка для VRChat: `rtspt://адрес:порт/phone`. Нужны открытые порты TCP `порт+11` и UDP `порт+12`. Телефон без аппаратного кодировщика H.264 прямо на сервер вещать для VRChat не сможет (приложение предупредит): тогда вещайте через ПК.

В Linux может понадобиться `sudo ufw allow 4717/tcp`, `sudo ufw allow 5353/udp` и порты WebRTC на ПК (`порт+101` TCP и `порт+102` UDP).

```bash
cd mobile && flutter pub get
./tool/fetch_cloudflared.sh            # cloudflared для бесплатной ссылки с телефона (в репозиторий не кладётся)
flutter test && flutter build apk --release --target-platform android-arm64   # app-release.apk; тесты идут по одному файлу (dart_test.yaml): эфир гоняется в реальном времени
```

Для отладочной сборки на эмуляторе x86_64 скачайте и его: `./tool/fetch_cloudflared.sh all`. Проверки с настоящим интернетом запускаются вручную: `VRCAST_TEST_NET=1 flutter test test/links_test.dart` (YouTube: видео, плейлист и эфир на сервер). Тест настоящей ссылки Cloudflare: `VRCAST_TEST_CLOUDFLARE=путь/к/cloudflared flutter test test/cloudflare_tunnel_test.dart` (за VPN добавьте `VRCAST_TEST_BIND=адрес_сетевой_карты`).

Тесты: `npm test` (тесты с захватом экрана пропускаются без `DISPLAY`).

## Как пользоваться

1. Добавьте ссылку или файлы — либо откройте «Экран» и выберите монитор, окно или область.
2. Нажмите «Начать эфир».
3. Скопируйте ссылку сверху и вставьте в AVPro-плеер в мире.

В мире нужен **AVPro** и включённые **Untrusted URLs** — эта настройка задаётся отдельно для каждого аккаунта VRChat.

Все режимы подробно описаны в [руководстве](docs/GUIDE.md).

## Свой сервер одной командой

Нужен VPS с белым IP и Linux (Ubuntu, Debian, CentOS — любой с systemd). Зайдите на него по SSH и выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/Kevanko/VRCast-Bridge/main/server/install.sh | sudo bash
```

Через минуту скрипт покажет адрес и ключ. В программе откройте Настройки → Сеть и серверы → «Добавить сервер» → «Уже настроен», вставьте их и сверху выберите «Свой сервер». Ссылка для VRChat — `rtspt://адрес:8554/live`.

Если порт 8554 занят, задайте другой: `curl … | sudo VRCAST_PORT=9554 bash`. Если у хостера есть файрвол в панели, откройте там этот порт по TCP.

На сервере появится команда `vrcast`:

| Команда | Что делает |
|---|---|
| `vrcast status` | работает ли сервер и сколько подключений |
| `sudo vrcast key` | ещё раз показать адрес и ключ |
| `sudo vrcast update` | обновить до последней версии, ключ сохранится |
| `sudo vrcast restart` | перезапустить |
| `vrcast logs` | последние строки журнала |
| `sudo vrcast uninstall` | удалить сервер и закрыть порты |

Можно и без консоли: «Добавить сервер» → «Настроить с нуля» — программа сама зайдёт по SSH с паролем root (пароль не сохраняется).

## Устройство

```
источник (экран или видео) → ffmpeg ┬→ RTSP-сервер → ссылка для VRChat
                                    └→ HLS-релей   → запасная ссылка и предпросмотр
```

Видео кодируется один раз и расходится в два канала. Формат кадра закреплён за сеансом эфира, поэтому смена источника не заставляет плеер переинициализировать декодер — из-за этого раньше и приходилось жать resync.

Ядро — Node.js без внешних зависимостей в рантайме. Оболочка — WinForms и WebView2. Захват звука — компонент на C# с NAudio, захват окон — на Rust через Windows Graphics Capture.

## Сборка

```powershell
git clone https://github.com/Kevanko/VRCast-Bridge.git
cd VRCast-Bridge
npm install
powershell -ExecutionPolicy Bypass -File tools/fetch-tools.ps1

dotnet publish audio-helper/VRCast.AudioCapture.csproj -c Release -o audio-helper/bin/publish
copy audio-helper\bin\publish\VRCast.AudioCapture.exe tools\
cargo build --release --manifest-path capture-helper/Cargo.toml
copy capture-helper\target\release\vrcast-window-capture.exe tools\VRCast.WindowCapture.exe

dotnet publish launcher/VRCastBridge.Launcher.csproj -c Release -o launcher/bin/publish
powershell -ExecutionPolicy Bypass -File tools/sign.ps1
```

`npm test` — 45 интеграционных проверок: поднимают настоящий сервер и гоняют через него реальный поток — задержку, стабильность при снижении битрейта, переключение источников, восстановление после сбоев.

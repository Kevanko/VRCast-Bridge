# Linux, телефон и сборка

Подробности, которые не поместились в README.

## Linux

Запуск из исходников (нужны Node.js 20+ и `ffmpeg`; `yt-dlp`, MediaMTX и cloudflared программа докачает сама или возьмёт из `PATH`):

```bash
git clone https://github.com/Kevanko/VRCast-Bridge.git && cd VRCast-Bridge
npm ci && ./bin/vrcast install      # зависимости и оболочка (Electron)
ln -s "$PWD/bin/vrcast" ~/.local/bin/vrcast
vrcast                              # окно приложения; vrcast stop|status|log
```

Оболочка (`desktop/`, Electron) повторяет Windows-версию: окно со страницей сервера, значок в трее (в GNOME нужно расширение AppIndicator), крестик прячет в трей, вопросы при выходе про идущий эфир и несохранённый список, перетаскивание файлов, выбор области экрана и подсветка источника, запоминание размера окна. Без неё `vrcast` откроет окно Chrome. Данные лежат в `$XDG_DATA_HOME/VRCastBridge` (по умолчанию `~/.local/share/VRCastBridge`), адрес — `http://127.0.0.1:4717`.

| Что | Как работает в Linux |
|---|---|
| Экран, монитор, область, окно | X11 через `x11grab`; список мониторов — `xrandr`, окон — `xprop` и `xwininfo`. В Wayland захват идёт через XWayland и видит только X11-окна |
| Звук | PulseAudio / PipeWire (`pw-dump` или `pactl`): системный звук, выбранный выход или микрофон. Звук одного приложения не вырезается — берётся весь системный |
| Автообновление, захват окна через Windows Graphics Capture, регулировка звука приложений | Только Windows |

Если MediaMTX не стартует с ошибкой `inotify: too many open files`, поднимите лимит: `sudo sysctl fs.inotify.max_user_instances=512`.

### Приложение для телефона (Android)

Приложение из `mobile/` (Flutter) одно и работает с ПК и без него: отдельного режима нет. Телефон хранит у себя файлы, серверы и копию настроек ПК; когда подключён к ПК, они объединяются в группу.

- **Устройства в сети.** В настройках ПК включите «Пульт для телефона»: ПК объявится в сети (`_vrcast._tcp`). Приложение показывает найденные ПК под их именами, замком отмечает защищённые PIN-кодом, а любое устройство можно назвать по-своему (имя хранится на телефоне). Имя ПК и необязательный PIN задаются в его настройках («Имя этого ПК в сети», «PIN для подключения»), там же список привязанных устройств с переименованием и отвязкой. PIN защищает управление; сам поток в сети открыт, как и ссылка RTSP.
- **Эфир в реальном времени** (SSE `/api/events`): что играет, статус, превью, очередь, ссылки; пауза, перемотка, скорость, повтор, громкость, переход по очереди.
- **Группа устройств.** ПК, к которому подключились, — админ; все подключённые устройства равны. Файлы и серверы каждого видны всем в общем списке с пометкой владельца, пока устройство подключено; отключилось (через 15 с без связи), и они пропадают у остальных. Файлы остаются на телефоне, ПК играет их по сети (`/api/media/<id>?k=<ключ>` на телефоне, ключ у каждого запуска свой). Эфир один, на одной ссылке, и им управляет тот, кто начал последним; перехватить его можно с любого устройства кнопкой «Перехватить». Остановить эфир, сменить очередь или ссылку может любое устройство. Убрать устройство из группы может только админ; если кто-то убрал чужой файл из очереди, владелец узнаёт об этом и убирает его у себя. Пока телефон спит или приложение закрыто, его файлы недоступны админу.
- **Пульт в браузере телефона, без установки.** На ПК: Настройки → Программа → «Доступ с других устройств» — включить; ниже появится QR-код. Наведите на него камеру телефона (в одной сети Wi-Fi) — в браузере откроется страница `/m`, сама привяжется по коду из QR и покажет: «Сейчас» (пауза, перемотка, далее, громкость, скорость, повтор, начать и остановить эфир, «Транслировать экран ПК»), «Очередь» (ссылки YouTube, Rutube, VK и других, файлы с телефона загрузкой, порядок, удаление), «Ссылки» (для плеера и быстрая, с копированием) и «Ещё» (качество, кадры, куда идёт эфир). Ключ остаётся в браузере телефона; «Забыть этот телефон» и «Отвязать» на ПК его отключают. Выключить программу, поменять папку кеша и серверы оттуда нельзя. Экран самого телефона из браузера транслировать нельзя (мобильные браузеры этого не дают): для этого есть приложение.
- **Админом может быть любое устройство.** Телефон: Настройки → «Это устройство — админ группы» (включено — другие устройства подключаются к нему по адресу и коду привязки, тот же протокол, что у ПК, порт меняется сразу; пока включено, приложение держит службу переднего плана). ПК подключается к другому устройству (ПК или телефону) в Настройках → Программа → «Подключиться к другому устройству»: вводятся адрес и код, доступ из сети включается сам (админ забирает ваши файлы по сети), кнопки «Пауза / играть», «Далее», «Стоп» и «Забрать эфир» управляют эфиром админа. Телефоны и ПК подключаются друг к другу в любых сочетаниях.
- **Своя очередь без ПК.** Без ПК очередь телефона работает сама: добавьте ссылку на YouTube (видео или плейлист, как на ПК: большой плейлист переспрашивает), прямую ссылку на mp4 или файлы с телефона. У каждого ролика название, длительность и обложка, их можно перетаскивать и смахивать. Ссылку телефон разбирает сам; поток берётся прямо перед запуском. YouTube в режиме «как в файле» — готовый mp4 (обычно до 360p); для HD выберите качество 480p, 720p или 1080p: тогда телефон сам берёт раздельные потоки и перекодирует. Прямые ссылки на mkv, webm, mp3, ogg, flac, wav, ts и HLS (`.m3u8`: записи и прямые эфиры, в том числе с шифрованием AES-128) телефон разбирает сам. Сам же он разбирает Rutube, VK, Twitch (каналы и записи), прямые эфиры YouTube и любые страницы, на которых лежит ссылка на видео (в том числе аниме-сайты): адрес страницы остаётся в очереди, а поток берётся прямо перед запуском. Телефон не запускает yt-dlp, поэтому сайты с хитрой защитой и закрытые видео (нужен вход в аккаунт, DRM, SAMPLE-AES) не откроются: ссылка в этом случае сообщит причину, а если подключён ПК, её можно добавить в его очередь. Очередь ПК без связи лежит отдельно (последняя копия, только для справки).
- **Эфир файлов с телефона без ПК.** Когда ПК не подключён, вкладка «Сейчас» становится плеером своей очереди (пауза, перемотка, следующий и предыдущий, повтор). Нажмите на свой файл в «Очереди» или «Начать эфир файлов». В режиме «Качество: как в файле» видео не перекодируется: приложение разбирает mp4/mov/m4a и отправляет кадры H.264 и звук AAC как есть, поэтому телефон не греется. Если нужны скорость, громкость, другое качество (480p, 720p, 1080p, 24/30/60 кадров, битрейт) или формат другой (HEVC, MKV, WebM, mp3, HLS), включается встроенный перекодировщик на аппаратных кодеках телефона: эфир всегда выходит в одном формате (H.264 + AAC 48 кГц стерео), поэтому плеер VRChat не переподключается при смене ролика. Скорость меняется без изменения тона. Вещать можно двумя способами, переключатель на той же вкладке:
  - **Свой сервер.** RTSP на ваш VPS, ссылка `rtspt://адрес:порт/phone` (та же, что у экрана телефона).
  - **Ссылка Cloudflare.** Бесплатная ссылка `https://….trycloudflare.com/stream/live.m3u8` прямо с телефона: приложение само раздаёт HLS, а `cloudflared` (внутри приложения) выводит его в интернет. Ссылка живёт, пока идёт эфир и приложение открыто. Мешают VPN, которые подменяют DNS или рвут порт 7844 (то же, что и на ПК).

  Пока идёт эфир, работает служба переднего плана (с уведомлением): экран можно гасить, и эфир не оборвётся. Эфир с телефона разряжает батарею и держит Wi-Fi включённым.
- **Экран или приложение с телефона в эфир.** Кнопка «Транслировать экран телефона» одна, путь выбирается сама: если ПК на связи, поток идёт через него (по WebRTC в MediaMTX на ПК, ПК кодирует эфир), иначе прямо на ваш сервер (VPS из `server/install.sh`, H.264). Android спрашивает: весь экран или одно приложение. Звук с телефона пока не передаётся.
- **Телефон подстраивается под ПК.** Сводка эфира всегда берётся с ПК, а запись экрана идёт в том же профиле: качество, частота кадров и битрейт следуют за настройками ПК.
- **Без связи.** Очередь, настройки и ссылки ПК сохраняются на телефоне и показываются без связи. Ссылки, добавленные без ПК, уходят в очередь ПК при подключении. Серверы личные: подключённое устройство делится ими с группой только на время подключения (для этого нужна привязка по коду), на самом ПК они не сохраняются.
- **Эфир на ПК с телефона.** Куда идёт эфир (локально, публичная ссылка, свой сервер), сервис быстрой ссылки, выбор сервера, прямой адрес, качество, кадры, кодировщик. Это требует привязки: код из «Настройки → Программа → Код привязки телефона» (или PIN ПК) вводится один раз. Без привязки настройки видны, но не меняются.
- **Что остаётся только на ПК:** папка кеша, добавление серверов по SSH, обновления, захват экрана и окон ПК, звук приложений и подготовка Unity. Это зависит от Windows и видеокарты ПК, телефон так не умеет. Телефон в свою очередь транслирует свой экран и файлы сам.

Для работы телефона без ПК сервер на VPS должен быть установлен или обновлён скриптом из этого репозитория («Настроить с нуля» в программе): он включает приём WebRTC и путь `phone`; ссылка для VRChat: `rtspt://адрес:порт/phone`. Нужны открытые порты TCP `порт+11` и UDP `порт+12`. Телефон без аппаратного кодировщика H.264 прямо на сервер вещать для VRChat не сможет (приложение предупредит): тогда вещайте через ПК.

В Linux может понадобиться `sudo ufw allow 4717/tcp`, `sudo ufw allow 5353/udp` и порты WebRTC на ПК (`порт+101` TCP и `порт+102` UDP).

```bash
cd mobile && flutter pub get
./tool/fetch_cloudflared.sh            # cloudflared для бесплатной ссылки с телефона (в репозиторий не кладётся)
flutter test && flutter build apk --release --target-platform android-arm64   # app-release.apk; тесты идут по одному файлу (dart_test.yaml): эфир гоняется в реальном времени
```

Для отладочной сборки на эмуляторе x86_64 скачайте и его: `./tool/fetch_cloudflared.sh all`. Проверки с настоящим интернетом запускаются вручную: `VRCAST_TEST_NET=1 flutter test test/links_test.dart` (YouTube: видео, плейлист и эфир на сервер). Тест настоящей ссылки Cloudflare: `VRCAST_TEST_CLOUDFLARE=путь/к/cloudflared flutter test test/cloudflare_tunnel_test.dart` (за VPN добавьте `VRCAST_TEST_BIND=адрес_сетевой_карты`).

Тесты: `npm test` (тесты с захватом экрана пропускаются без `DISPLAY`).


## Устройство

```
источник (экран или видео) → ffmpeg ┬→ RTSP-сервер → ссылка для VRChat
                                    └→ HLS-релей   → запасная ссылка и предпросмотр
```

Видео кодируется один раз и расходится в два канала. Формат кадра закреплён за сеансом эфира, поэтому смена источника не заставляет плеер переинициализировать декодер — из-за этого раньше и приходилось жать resync.

Ядро — Node.js без внешних зависимостей в рантайме. Оболочка — WinForms и WebView2. Захват звука — компонент на C# с NAudio, захват окон — на Rust через Windows Graphics Capture.

## Сборка

```powershell
git clone https://github.com/Kevanko/VRCast-Bridge.git
cd VRCast-Bridge
npm install
powershell -ExecutionPolicy Bypass -File tools/fetch-tools.ps1

dotnet publish audio-helper/VRCast.AudioCapture.csproj -c Release -o audio-helper/bin/publish
copy audio-helper\bin\publish\VRCast.AudioCapture.exe tools\
cargo build --release --manifest-path capture-helper/Cargo.toml
copy capture-helper\target\release\vrcast-window-capture.exe tools\VRCast.WindowCapture.exe

dotnet publish launcher/VRCastBridge.Launcher.csproj -c Release -o launcher/bin/publish
powershell -ExecutionPolicy Bypass -File tools/sign.ps1
```

`npm test` — 45 интеграционных проверок: поднимают настоящий сервер и гоняют через него реальный поток — задержку, стабильность при снижении битрейта, переключение источников, восстановление после сбоев.
